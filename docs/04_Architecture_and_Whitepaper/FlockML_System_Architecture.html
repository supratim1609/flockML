1. BitNet 1.58b Quantization

Standard LLMs require FP16 (16-bit floating point) weights. A 70 Billion parameter model requires ~140 GB of VRAM, making it impossible to run on consumer hardware.

FlockML utilizes ternary weight quantization, clamping all parameter weights strictly to [-1, 0, 1].

W' = Round(Clip(W / γ, -1, 1))
γ = Mean(|W|)

By utilizing only three states, the model operates at exactly 1.58 bits per parameter (since log2(3) ≈ 1.58). This results in an 80.2% reduction in VRAM footprint with near-zero degradation in perplexity.

2. Memory Sharding Physics

Even quantized, a 70B model requires ~13.8 GB of VRAM. Standard browsers crash when allocating more than 4GB. FlockML solves this by mathematically sharding the layers across the WebRTC sybil ring.

Target Model Required VRAM Nodes in Mesh VRAM Per Node
Llama 3 8B (Quantized) ~1.6 GB 10 Nodes ~160 MB
Llama 3 70B (Quantized) ~13.8 GB 50 Nodes ~276 MB
Llama 3 405B (Quantized) ~80.0 GB 500 Nodes ~160 MB

Zero-Copy DMA: By using WebAssembly (Wasm) `SharedArrayBuffer`, FlockML maps the sharded 276MB weights directly into the browser's WebGPU pipeline without copying it into JavaScript memory, eliminating garbage-collection latency entirely.
